// What is the difference between < section >, < article >, < aside >, and < main >?
            
📚 1. < section >
    What it is: A section of related content.
    Use when: You have a logical grouping of content, like a group of FAQs or service listings.
                        
📰 2. < article >
    What it is: A self-contained piece of content that can stand alone.  
    Use when: You’re writing things like blog posts, news articles, comments, or forum posts.
                        
📎 3. < aside >
    What it is: Content that is related to the main content, but not essential.
    Use when: You have sidebars, tips, quotes, ads, or related links.    
                        
🧱 4. < main >
    What it is: The main content of the page. Should be unique — only one 
 per page.
    Use when: You want to wrap all the central, meaningful content (excluding headers, nav, sidebars, footers).    


    < h1>Welcome to My Blog
    < article>...< /article>

🧠 1. localStorage
=> Persists even after the browser is closed
=> Data is stored indefinitely until cleared by the user or your code
=> Stores data as key-value pairs
=> Limit: ~5MB
=> Only accessible via JavaScript (not sent with requests)
=> You need to keep data long-term (e.g., user preferences, theme selection).
example.
    localStorage.setItem("theme", "dark");
    //console.log(localStorage.getItem("theme")); // "dark"
    Common uses::	Preferences, themes


🕒 2. sessionStorage
    => Cleared when the tab or window is closed
    => Same API as localStorage
    => Limit: ~5MB
    => Useful for temporary data (like form state) 
    => Data should only last for the duration of the tab session.
    example.
    sessionStorage.setItem("tempScore", "100");
    //console.log(sessionStorage.getItem("tempScore")); // "100" 
    Common uses::	Temp forms/data
                            
            
🍪 3. cookies
    => Small pieces of data (limit ~4KB per cookie)
    => Can be set to expire at a specific time
    => Automatically sent with every HTTP request
    => Accessible from both JavaScript and server-side
    => Used for authentication, tracking, and session handling
    => You need to send data to the server on every request (e.g., auth tokens).
    example.
    document.cookie = "username=John; expires=Fri, 1 May 2025 12:00:00 UTC; path=/";
    Common uses::	Auth, sessions

                        // What is the purpose of srcset in the < img> tag?
                        🎯 Purpose of srcset
                            => srcset allows you to define multiple image files for the browser to choose from based on:
                            => Screen size
                            => Device resolution (e.g., retina displays)
                            => This improves:
                            => Page speed (by loading smaller images on small screens)
                            => Clarity (by loading high-res images on retina screens)
            
                        // example:
                            < img 
                                src="small.jpg" 
                                srcset="small.jpg 480w, medium.jpg 768w, large.jpg 1200w" 
                                sizes="(max-width: 600px) 480px, (max-width: 1000px) 768px, 1200px" 
                                alt="A scenic mountain view">
                            
                        // How it works:
                            => srcset gives the browser multiple image sources with their widths (w = pixels).  
                            => sizes tells the browser how much screen space the image will use under different conditions.
                            => The browser picks the best image based on current screen width + resolution.    
            
                    
                
                    
                        🌟 // What is Shadow DOM?
                            The Shadow DOM is a browser feature that lets you attach a hidden, separate DOM tree to an element — one that is isolated from the main DOM.
                            //OR
                        // The Shadow DOM is a part of the Web Components standard that allows you to create encapsulated DOM trees — meaning elements can have their own isolated structure and styles.   
                            => It's like giving an element its own private part of the page that:
                            => Has its own elements and styles
                            => Is not affected by outer page styles
                            => Doesn’t mess up your global CSS or scripts
                            It’s like giving a component a private, hidden DOM that:
            
                            => Has its own HTML elements
                            => Has its own CSS
                            => Doesn’t clash with the rest of the page
            
            
                            🧱 Why Shadow DOM Exists
                            In regular HTML:
                            => Styles and scripts are global.  
                            => Components can interfere with each other (CSS leaks).               
                            => With Shadow DOM:                
                            => You can build self-contained components that work anywhere, without breaking other code or styles.

                        // What are datalist and autocomplete used for?
            
                        //< datalist> Element
                            => Purpose: The < datalist> element is used to define a list of predefined options for an < input> element, providing users with a set of suggestions as they type.
                            => When to use: You can use it when you want to offer users suggestions based on a set of predefined options, making it easier for them to select values.
                        
                            < form>
                                < label for="fruit">Choose a fruit:< /label>
                                < input list="fruits" id="fruit" name="fruit" />
                                < datalist id="fruits">
                                < option value="Apple">
                                < option value="Banana">
                                < option value="Cherry">
                                < option value="Date">
                                < option value="Elderberry">
                                < /datalist>
                                < input type="submit" value="Submit" />
                            
            
                        => What happens: When the user starts typing in the < input> field, the browser will show a dropdown with the options ("Apple", "Banana", etc.) defined in the < datalist>.
                        => Note: The user can still enter their own value if it's not in the list. 
                        
                        //🔹 autocomplete Attribute
                            => Purpose: The autocomplete attribute helps the browser remember and suggest previously entered values for form fields, improving usability by reducing repetitive input.
                            => When to use: It’s particularly useful for form fields that users often fill out, such as email addresses, names, or addresses, enabling them to automatically fill in previously used values.
                            
                            < label for="email">Email:< /label>
                            < input type="email" id="email" name="email" autocomplete="on" />
            
                        //What happens:
                            => The email input field will show previous email addresses that the user has typed in.  
                            => The password input field will not show any previous passwords (because autocomplete="off").

                  // What is the difference between relative, absolute, fixed, and sticky positioning?
              
                  // 1. Relative
                      => The element is positioned relative to its normal position.
                      => It moves, but doesn’t affect other elements.
                      => The "gap" it leaves behind stays.

                  //2. Absolute
                      => The element is positioned relative to the nearest positioned ancestor (relative, absolute, or fixed).
                      => If no positioned ancestor is found, it positions relative to the < html> (viewport).
                      => It’s completely removed from the normal document flow.    
              
                  //3. Fixed
                      => The element is positioned relative to the browser window (viewport).
                      => Does not move when you scroll!
                      => Always stays at the same place.

                  // 4. Sticky
                      => It’s a hybrid of relative + fixed.
                      => The element acts like relative until a scroll threshold is reached, then sticks like fixed.                
                      => Useful for sticky headers, sidebars, etc.    
              
          
              
                  // 1. px (pixels)
                      => Fixed size unit.
                      => Not responsive — size stays the same no matter parent or root.
                      => 1px = 1 pixel on the screen.

                  //2. em (relative to parent)
                      => Size is relative to the parent’s font-size.
                      => Multiplies down the hierarchy (can cascade).
                      
                  // 3. rem (relative to root)
                      => root em. 
                      => Always relative to the < html> font-size.
                      => Consistent scaling across the page — does not depend on parent elements.    
                  
                  => px = Absolute.
                  => em = Relative to parent.     
                  => rem = Relative to root.
          
                  
          
              
                  // px, em, rem, %, vh — Quick Comparison

                   => Unit || Stands for || Based on || Good for || Example
                   => px || Pixels || Fixed size || Absolute measurements (e.g., borders) || font-size: 16px;
                   => em || Relative to parent || Parent’s font-size || Nested scaling (can cascade) || font-size: 2em;
                   => rem || Root em || < html> font-size || Consistent scaling across the page || font-size: 1.5rem;
                   => % || Percentage || Relative to parent element || Responsive sizing || width: 50%;
                   => vh || Viewport height || 1% of viewport’s height || Full-screen sections || height: 100vh;

                  => z-index is a CSS property that controls the vertical stacking order of overlapping elements.

                      => Lower z-index value = element appears behind.
                      => It only works on elements that have position set to something like relative, absolute, fixed, or sticky.
